# Use Effect for backend orchestration

Adopt Effect 4 services, typed failures, scopes, and serialization in the Electron-independent backend so dependencies, resource lifetimes, and operation ordering share one model. Main constructs one managed application runtime; the narrow desktop API remains plain data and Promises, and the Svelte Workspace session controller retains confirmed renderer state, preserving ADR-0004 and ADR-0005.

The rollout in [issue #91](https://github.com/Cahllagerfeld/tuxedo-app/issues/91) uses independently runnable PRs into the Effect integration branch. Workspace lifecycle operations establish the built-in `effect/FileSystem` service with its Node layer and the date/identity service, one authoritative session and semaphore, and scoped atomic writes; Todo-item methods compose directly as Effects against that application layer; observation callbacks use the same state, serialization, and runtime. The owner approved folding Todo-item orchestration into this slice to remove Promise/Effect round trips and repeated service provisioning.

[Issue #97](https://github.com/Cahllagerfeld/tuxedo-app/issues/97) gives each confirmed observation target a session-owned Scope. Platform adapters acquire directory watchers and subscriptions in that Scope; the session debounces raw signals and runs background reads in scoped fibers. Retargeting and disposal close watchers, subscriptions, queues, and pending debounce work together, including partially acquired resources. Observation failures remain best-effort, and narrow desktop events continue to refresh through Svelte's existing restoration path. Main-process shutdown admission and draining remain a dedicated later slice.

[Issue #98](https://github.com/Cahllagerfeld/tuxedo-app/issues/98) completes main-process ownership. `application-runtime.ts` wraps the established managed runtime with synchronous admission and a manually owned application Scope (Effect 4's public `Scope.makeUnsafe` at the synchronous Promise bridge). Main owns scoped Electron adapters for startup, activation, the Todo-file dialog, IPC, protocol/security handlers, and windows; each window has a child Scope that releases its native-theme subscription on close. Domain services remain Electron-independent and the renderer ownership in ADR-0005 remains unchanged.

On normal quit, `before-quit` prevents Electron's immediate exit and synchronously closes both desktop and observation admission. Already admitted requests retain their ordering through the session semaphore and finish before observers, application/window Scopes, and runtime resources close. Disposal is idempotent; startup failure follows the same cleanup path. The Promise boundary tracks admitted work rather than introducing another domain queue. Runtime disposal alone interrupts fibers, so it is deliberately last (see upstream `packages/effect/test/ManagedRuntime.test.ts`, “fibers are interrupted on dispose”; resource ownership follows `ai-docs/src/01_effect/05_resources/10_acquire-release.ts` and the public `Scope.fork`/`Scope.close` APIs in the version-matched 4.0.3 subtree).

One 10-second wall-clock deadline covers drain, observation release, platform release, and runtime disposal. Timeout diagnostics identify the blocked phase and pending operation names; cleanup failure logs its cause. Normal completion resumes Electron quit with exit code 0. Startup failure, cleanup failure, or timeout exits with code 1; timeout does not retry, roll back, or claim safety for an ambiguous write. Forced termination (including this fallback) can interrupt a write; the deadline preserves a usable quit even when a platform callback or finalizer never returns.
