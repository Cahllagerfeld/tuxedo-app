# Coding Standards

## Layering

- `apps/desktop/src/lib`: `app` (wiring) → `modules/<name>` (domain, state, UI, tests together) → `shared` (feature-free).
- Modules import only themselves and `shared`; cross-module imports mark real domain coupling.
- Routes stay thin: compose app, module UI, shared UI.

- Private `@tuxedo/desktop` owns renderer, Electron integration, managed application runtime, Promise bridge, native adapters, and app tooling. Private `@tuxedo/backend` owns Electron-independent domain Effects and scoped Layers; its public entry point exposes Workspace session operations, Layer composition, and filesystem/identity/observation injection. Keep parsing, persistence, and session implementation details private. Backend imports contracts and its Node/Effect dependencies; it cannot depend on desktop or renderer code. `@tuxedo/contracts` exports browser-safe TypeScript schemas, DTOs, validation, desktop client types, and form constraints; it cannot depend on Node, Electron, Svelte, or desktop code. Consume its explicit package exports, never desktop-relative contract copies. Workspace imports must remain bundled in the shipped app.

## Svelte

- `$derived` > event handler > explicit API; `$effect` only for external systems, justified in review.

## UI

- shadcn-svelte primitive first; missing → shadcn CLI.
- Tailwind only; `<style>` for what Tailwind cannot express.
- Forms: shadcn `Form` + Formsnap + Superforms + Effect Schema, `Form.Field` → `Form.Control` → input → `Form.Description`/`Form.FieldErrors`.

## Desktop contract and ownership

- Electron-independent domain operations in `packages/backend` own filesystem access, persistence validation, todo.txt parsing, operation serialization, and atomic writes. Electron main supplies platform integration and IPC transport.
- The renderer uses only the narrow `window.desktop` preload API. Shared channel/request/response types and runtime schemas in `packages/contracts/src/contract.ts` (imported through `@tuxedo/contracts`) validate both transport directions; change main, preload, renderer, and contract tests together.
- Treat the narrow preload interface as RPC: explicit validated inputs and plain Promise results. `WorkspaceCommands` owns command admission, progress, and contextual failures; displayed backend data comes from route-data getters. Commands invalidate affected loader dependencies before releasing admission. Keep backend scope/revision/Workspace/path checks; derive counts and facets from the loader's Todo file. Route components compose UI; drafts, dialogs, filters, focus, and selection stay local.
- SvelteKit `load` functions own all displayed backend data: root layout reads the shared session, the Workspace page reads its destination by ID, and the Workspace layout reads scoped saved views. Loaders remain pure and safe to preload. Commands and external-change notifications use targeted invalidation, with no second renderer snapshot store or publication handshake. `readSession({})` and `readWorkspace({ workspaceId })` never activate a Workspace or change Undo. Explicit `refreshSession({})` reconciles disk at host startup and read-only recovery, preserving revision, Undo, and observation when unchanged. Failed reads retain matching displayed contents and block stale writes while permitting Retry, Home, and window lifecycle. Lost or ambiguous write responses recover through reads; a saved write is never resubmitted automatically.
- SvelteKit owns destinations and history. Activate only at committed `afterNavigate`; native `navigating` and synchronous command admission gate competing work. Only that committed edge bypasses SvelteKit's still-present in-flight flag. Preloads never activate a Workspace or consume Undo. Startup resumes once with replacement; explicit Home preserves selection and Undo; creation accepts its returned session without another activation.
- `SavedViewsResource` reads the current Workspace's views and read errors from its loader. Saved-view writes share Workspace command admission and invalidate only their saved-view dependency; Todo-file changes never reread saved views. Reset identity-sensitive UI on true Workspace changes and keep components mounted during ordinary same-Workspace updates.
- Test backend public operations with real temporary files, command/resource behavior through typed desktop adapters, reactive UI integration with Svelte harnesses, and actual routing/preload/IPC through real Electron. Use explicit deferred boundaries for races. Renderer imports cannot expose Node/Electron capabilities; backend domain modules remain Electron-independent.

## Shared Schema validation

- Effect 4 Schema is canonical for desktop requests, responses, observation events, persisted catalogues, and forms. Reuse shared constraints from `@tuxedo/contracts`; do not add parallel validator definitions.
- Forms use Superforms `standard`/`standardClient` with `Schema.toStandardSchemaV1` and explicit defaults. Keep form strings distinct from nullable/optional desktop dates and preserve field error paths.
- Decode Effect desktop payloads synchronously with strict excess-property checks, retaining plain DTOs and Promise-based operations. Use `effectValidator` at desktop and persisted-data boundaries. Empty requests use `Schema.Record(Schema.String, Schema.Never)` because an empty `Struct` accepts excess properties.

## Backend Effect orchestration

- Main constructs one managed application runtime; desktop handlers retain plain Promise-based requests and responses. `apps/desktop/electron/session-runtime.ts` owns runtime composition and the desktop Promise bridge, consuming the public `@tuxedo/backend` entry point. `workspaceSessionLayer` composes domain services and captures injected capabilities without constructing a managed runtime. `WorkspaceCatalogue` owns strict disk reads, decoding, and atomic catalogue persistence; only Workspace lifecycle initialization treats a missing catalogue as empty. `WorkspaceSession` captures its implementation dependencies during layer construction, so callers require only the session service. `WorkspaceSession` in `session.ts` owns the authoritative confirmed state and one Effect semaphore for all lifecycle, Todo-item, and observation operations. `workspace-lifecycle.ts` owns Workspace lifecycle decisions and returns loaded data for the session to accept; `todo-operations.ts` uses that same session state.
- `application-runtime.ts` owns synchronous desktop/lifecycle admission, tracking of admitted work, and the application Scope around that managed runtime. Main runs startup, activation, dialogs, and IPC only at lifecycle/transport edges; Electron calls remain thin scoped adapters. Window child Scopes release native-theme subscriptions and windows; the application Scope releases IPC handlers, protocol and permission/header handlers, and platform subscriptions, including on startup failure.
- Normal quit closes desktop and observation admission synchronously, drains admitted requests (including queued requests), stops observation, closes platform Scopes, then disposes the runtime. Do not dispose the runtime or close observers ahead of an admitted mutation's commit and confirmation. A 10-second wall-clock deadline covers the whole sequence; log the blocked phase and pending operation names and exit with code 1 on timeout/failure. Never retry ambiguous writes; forced exit can interrupt a write. Repeated quit/disposal requests share completion.
- Todo-file observation adapters acquire watchers and subscriptions in the supplied Scope and emit raw change signals. The session owns each confirmed target's Scope, signal queue, and 250 ms stream debounce; authoritative refresh work runs in the application session Scope through the same semaphore, retaining a current-target dirty marker while work is pending. Accept refreshed contents before notifying the renderer, which invalidates affected route data and retains relevant events arriving during admitted work. Same-target revisions preserve the observer; retargeting, Empty/unavailable states, and runtime disposal close that Scope. Observation acquisition and release failures stay best-effort, and callbacks from released targets cannot emit desktop events.
- Use `effect/FileSystem` with `@effect/platform-node/NodeFileSystem.layer`; inject that service and date/identity capabilities rather than adding a parallel filesystem adapter. Keep parsing and line transformations as functions. Map expected typed operation failures to existing outcomes; log unexpected defects with the operation name and return a safe message.
- Atomic persistence acquires exclusive adjacent temporary files in a scope, preserves permissions, synchronizes, closes before rename, and cleans up on failure. Protect replacement and confirmed-state acceptance together from interruption. Backend operations compose as Effects against the application layer; convert to Promises only at the desktop edge. Observation callbacks enter through that same managed runtime.
- Use `@effect/vitest` for Effect-native tests with scoped fixtures; retain plain Vitest tests for the desktop Promise API in the desktop project. Backend tests build actual scoped Layers and never import desktop runtime helpers. Filesystem tests use live services (`it.live` or `layer` with `excludeTestServices`).
