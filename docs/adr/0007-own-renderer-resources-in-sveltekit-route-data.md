# Own renderer resources in SvelteKit route data

Simplified by [ADR-0008](0008-simplify-loader-owned-dataflow.md), which retains loader ownership and replaces the publication handshake with ordinary targeted invalidation.

SvelteKit client loaders solely own the renderer catalogue, Workspace/Todo-file/preferences, and saved-view resources. This supersedes ADR-0005's controller snapshots and mount-driven initialization for [spec #180](https://github.com/Cahllagerfeld/tuxedo-app/issues/180). Root layout, Workspace page, and Workspace layout declare independent typed IPC dependencies; Todo invalidation never rereads saved views. The backend remains the authoritative domain owner under ADR-0004 and ADR-0006.

Repeatable reads carry speculative or confirmed provenance and cannot activate, retarget observation, advance authoritative revisions, or consume Undo. Actual committed destinations activate through `afterNavigate`; `beforeNavigate` only admits or cancels navigation. Native `navigating` also gates commands because SvelteKit 2.70.3 skips `beforeNavigate` on supersession and clears its reactive navigation flag after `afterNavigate`. Startup resumes once with history replacement, Home preserves selection/Undo, and creation hands off its already committed activation receipt.

The command coordinator contains admission, progress, outcomes, and confirmation/recovery metadata, and reads current resources through getters. Command DTOs never become renderer snapshots. Admission remains held through targeted invalidation and published identity/scope/revision confirmation, including superseded invalidations that resolve without publication. Inactive speculative data never authorizes writes. Native dependencies use `tuxedodata:`: reusing the app's `tuxedo:` scheme would resolve identifiers relative to Home or nested destinations in the packaged browser.

Native thrown loader failures replace the reader branch. Expected read failures instead return the matching current resource from `$app/state.page.data` with error metadata, retaining contents and ordinary same-Workspace UI without another store. A committed write or activation followed by refresh failure releases ordinary busy state, preserves its minimal receipt, blocks stale writes, and offers read-only Retry and safe navigation. Recovery never repeats the committed operation. Actual Workspace changes reset identity-sensitive UI.

Observation uses the backend semaphore to accept authoritative refreshes before notification. Its stable current-target observer and focused dirty marker account for relevant signals during admitted work; released targets cannot affect another Workspace. Renderer events invalidate only affected resources and survive pending command refreshes. Existing atomic persistence, conflict checks, scoped identities, and shutdown guarantees remain.

Verification uses typed desktop/resource and Svelte UI seams plus the actual installed router in Electron and the copied macOS app outside the checkout. Controlled IPC gates cover preloading, supersession, delayed publication, retained failure, committed activation, read-only recovery, and observation during work. Effect 4.0.5 source evidence for session-scoped background work is `Effect.forkIn` in `packages/effect/src/Effect.ts` and its interruption test in `packages/effect/test/Effect.test.ts`; resource ownership follows `ai-docs/src/01_effect/05_resources/10_acquire-release.ts` in the read-only upstream checkout.
